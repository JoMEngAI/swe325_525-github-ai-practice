GitHub concepts

Repository:
A repository stores project files and their version history. This repository contains Markdown documentation for the assignment.

Issue:
An issue records a task, problem, or proposed improvement. My issue defines the assignment work and the acceptance criteria used to check it.

Branch:
A branch provides a separate line of development. The feature/github-ai-workflow branch is used to prepare the assignment documentation without directly changing the default branch.

Commit:
A commit records a snapshot of selected changes. Specific commit messages explain the purpose of each change.

Pull request:
A pull request proposes merging changes from one branch into another. It provides a place to inspect the changes, discuss them, and record review feedback.

Default branch:
The default branch is the repository's primary branch. In this repository, the default branch is main. It will contain the reviewed assignment documentation after the pull request is merged.

How the workflow objects relate

The issue defines what should be completed and how success will be checked.

The feature branch keeps the assignment changes separate from main while the documentation is developed.

The commits record meaningful steps in producing the documentation.

The pull request gathers the proposed changes for review and references the issue.

The review checks the proposed changes against the acceptance criteria and records feedback.

Merging the pull request brings the reviewed documentation into main.

The issue, commit history, pull request, and retained feature branch provide evidence of the completed workflow.
